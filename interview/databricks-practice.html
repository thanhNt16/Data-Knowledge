Databricks Practice Drill ​

Why it matters — The cert isn't testing whether you can recite docs; it's testing platform fluency: which tool solves which problem, which command does which mutation, which default bites you. Drill these sets the way you'd drill rapid-fire questions — answer before you reveal, and send every miss back to the real chapter (Delta and the lakehouse live under Lakehouse Platforms; the platform itself is vendor-agnostic, so every miss is also a concept gap, not just a product gap).

What this exam actually tests ​

The blueprint skews hard toward Delta Lake and everyday SQL/Spark work on the platform — expect roughly this mix, mined from a full practice bank and weighted against the published outline:

Topic clusterRough shareWhere to study it on this site
Delta Lake & lakehouse fundamentals (ACID, storage layout, time travel, VACUUM, OPTIMIZE, medallion, Photon)~25%Lakehouse Platforms, File Formats, Storage Architectures
Platform & governance (control/data plane, Unity Catalog, ownership, cluster pools, SQL warehouses)~15%Lakehouse Platforms, Platform Deep Dive, Cost & Architecture
Ingestion & ELT on the platform (COPY INTO, Auto Loader, JDBC, MERGE, UNION, external vs managed tables, UDFs)~15%ETL / ELT / CDC, SQL Advanced Queries, Spark Architecture
Structured Streaming & checkpointing (triggers, WAL, micro-batches)~10%Windows & Watermarks, Batch vs Stream
Lakeflow / Delta Live Tables & data quality (streaming vs live tables, expectations, pipeline UI)~10%Data Quality, Orchestration
Workflows & day-to-day operations (multi-task jobs, schedules, Repos, compute sizing)~10%Orchestration, dbt
Everything else (MLflow mentions, BI/dashboards, misc SQL)~15%System Design practice, SQL Coding

Two traps the exam loves: tool-for-job questions (Auto Loader vs COPY INTO vs JDBC vs Delta Live Tables — pick the tool, not the feature list) and state questions (where does the checkpoint live, what does VACUUM delete, what does DROP TABLE leave behind). The sets below are written to hit both.

🧠 Practice sets ​

Six themed sets, five to six questions each. Answer every card before revealing — these are written to mimic the real thing's scenario-first style, not trivia recall.

Set 1 — Lakehouse & Delta fundamentals

🧠 Check yourself

Q1. Analysts and engineers keep publishing conflicting numbers from siloed copies of the same data. Which property of a lakehouse fixes this at the architecture level?

Q2. Two jobs run against the same Delta table and one does not leave the table half-written or corrupted. What provides that guarantee?

Q3. Which description of a Delta table on storage is accurate?

Q4. An engineer needs to remove every row where age is greater than 25 from an existing Delta table. Which statement does it?

Q5. Time travel to a three-day-old version fails because the underlying data files are gone. What most likely deleted them?

Set 2 — Platform, governance & compute

🧠 Check yourself

Q1. In the classic Databricks architecture, which component lives entirely in the control plane?

Q2. A nightly job must start producing a report within seconds of its trigger, and cold cluster-start latency is the bottleneck. What helps most?

Q3. An engineer leaves the company and their Delta tables need a new owner, but the departing engineer no longer has access. Who can transfer ownership?

Q4. Which advantage do Databricks Repos give you over a notebook's built-in version history?

Q5. Which Git operation can NOT be performed inside Databricks Repos?

Set 3 — Ingestion & SQL/Spark on the platform

🧠 Check yourself

Q1. A shared landing directory accumulates files from several processes that cannot be moved or deleted. The pipeline must pick up only new files each run. Which tool fits?

Q2. A daily COPY INTO job runs against yesterday's file in /transactions/raw, but the row count in the target table does not change. Most likely cause?

Q3. An engineer must build a Delta table from an existing SQLite database. Which clause completes CREATE TABLE ... USING ___?

Q4. The engineering team writes tests in Python but needs to read the analyst-created table sales. Which PySpark call accesses it?

Q5. Two monthly tables, march_transactions and april_transactions, have no overlapping rows. Which builds one deduplicated all_transactions table?

Q6. A nightly job must upsert records into a Delta table without writing duplicates. Which command is built for that?

Set 4 — Structured Streaming & medallion

🧠 Check yourself

Q1. Structured Streaming must record the exact offsets processed per trigger so a failed query can restart and reprocess correctly. Which two mechanisms does it use?

Q2. What actually powers Auto Loader's incremental file processing?

Q3. A streaming write should run a micro-batch every 5 seconds. Which trigger option does that?

Q4. Which statement best describes Bronze tables relative to the raw files?

Q5. How do Gold tables differ from Silver tables?

Set 5 — Lakeflow / DLT & data quality

🧠 Check yourself

Q1. A team wants pipeline-level data quality monitoring that can drop or flag bad records automatically as data lands. Which tool?

Q2. A pipeline declares CONSTRAINT valid_ts EXPECT (ts > "2020-01-01") ON VIOLATION DROP ROW. What happens to violating records?

Q3. Some records are being dropped somewhere in a three-table DLT pipeline. How does the engineer find which table is dropping them?

Q4. When should you use CREATE STREAMING LIVE TABLE instead of CREATE LIVE TABLE?

Q5. A DLT pipeline in production runs in Continuous mode. After Start is clicked with valid definitions and pending data, what happens?

Q6. Which streaming query shape represents a Silver-to-Gold hop?

Set 6 — Workflows, SQL & day-to-day operations

🧠 Check yourself

Q1. A morning job has one task. A new notebook must run before it to fix upstream data. What is the cleanest setup?

Q2. A manager wants a Databricks SQL query refreshed every minute for one week after launch — and zero cost after that. What enforces the stop?

Q3. Many analysts run small queries concurrently on one always-on SQL warehouse and latency is climbing. Which change helps?

Q4. An analyst's SQL script must run daily, but its final query only on Sundays. What is the practical approach?

Q5. A DROP TABLE removes my_table from SHOW TABLES, but the data files are still sitting in storage. Why?

Q6. A SQL UDF is needed to apply custom logic to stores.city at scale. Which statement creates one?

💡 How to run the drill

Do one set a day, cold. For every miss, write one line about the rule you broke (e.g. "VACUUM deletes files, not history"), then re-read that section of the linked chapter. Re-run missed sets after 48 hours — spaced repetition is what turns these into reflexes, same cadence as the rapid-fire drill.
